# 대상 신원 이중 검증

내부망 점프 실패 시 Bastion 자신의 세션이 내부망 장비 이름으로 오인 저장될
뻔한 사고(ns0281, ns0282)를 계기로, 세션의 프롬프트와 수집한 설정 양쪽에서
장비 이름을 인벤토리 대상 이름과 대조하는 이중 검증(대상 신원 확인)을
추가한다. 검증 실패는 전용 `HostnameMismatchError` 예외로 표현하여, 기존의
범용 `except Exception:` 절이 이를 다른 연결/수집 실패와 뭉뚱그리지 않고
구분된 실패 단계 메시지로 보고할 수 있게 한다.

## Considered Options

- 검증 실패를 일반 예외로 발생시키고 기존 `except Exception:` 절 안에서
  함께 처리한다 — 신원 불일치가 다른 연결/수집 실패와 같은 메시지로
  뭉뚱그려져 운영 결과 메시지의 실패 단계 구분이 흐려지므로 기각.
- 전용 `HostnameMismatchError` 예외 클래스를 도입한다 — 채택. 각 실패
  지점 앞에 `except HostnameMismatchError:` 절을 두어 "직접/내부망 대상
  장비 이름 불일치"라는 구분된 메시지를 보고할 수 있다.
